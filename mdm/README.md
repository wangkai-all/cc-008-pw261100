# 客户主数据整理工具

导入多个业务系统的客户资料，找出可能属于同一个人的记录，生成统一客户视图。
每个字段都能追溯来源系统与原值，合并可撤销，归属不明确的资料绝不丢弃。

## 运行

```bash
pip install flask          # 唯一第三方依赖
python3 seed_demo.py       # 初始化虚构演示数据（可重复执行，会重置 mdm.db）
python3 app.py             # 打开 http://127.0.0.1:5000
python3 test_e2e.py        # 端到端流程自测（独立临时库，不影响演示数据）
```

## 合并规则

| 情况 | 处理 |
|---|---|
| 已验证手机号/邮箱完全一致 + 姓名一致 | **自动合并** |
| 联系方式一致但姓名不同 / 未验证 | 人工确认列表 |
| 手机号指向客户A、邮箱指向客户B | 人工确认列表（冲突） |
| 仅姓名相同 + 地址相似 | 只推荐候选，不自动合并 |
| 同一来源同一 external_id 再次导入 | 更新来源版本（version+1），不新建客户 |

- 手机号/邮箱先规范化（去空格/分隔符/国家码、邮箱小写），原值保留在记录里。
- 合并前在「对比」页逐项选择每个字段保留哪个值；人工选过的字段**锁定**，
  后续低优先级来源导入不能覆盖（未锁定字段按来源优先级自动取值）。
- 所有合并操作（自动并入 + 人工合并）都留痕，可在「合并记录」撤销；
  撤销会还原客户、字段血缘、记录归属和待确认队列。
- 撤销时，合并期间新增且无法明确拆回的记录进入「归属冲突」，人工指定归属，不会丢失。

## 演示数据场景（demo_imports/）

种子脚本导入 01–04：

1. **共享手机号**：张伟（CRM `138-0000-1234` / 电商 `+86 138 0000 1234`，均已验证）→ 自动合并，客户#1 血缘里能看到两个来源的原值。
2. **同名不同人**：李娜（上海，CRM）与李娜（广州，客服）→ 各自独立，不会合并。
3. **手机号/邮箱冲突**：电商 S103 陈强，手机号指向 CRM 陈强、邮箱指向客服陈强 → 待确认列表。
4. **候选推荐**：两个王芳地址相似（文三路100号 / 同址2幢302室）→ 候选推荐。

页面上继续演示：

1. 「待确认」→ 王芳候选 → 对比字段并确认合并（逐字段选值，如选客服的地址）。
2. 「导入」`05_crm_update.json`（来源 CRM系统）→ C001 版本升到 v2，不新建客户。
3. 「导入」`07_support_update.json`（来源 客服系统）→ 锁定的地址不被覆盖。
4. 「导入」`06_crm_wangfang.json`（来源 CRM系统）→ 新王芳自动并入已合并客户。
5. 「合并记录」→ 撤销王芳的人工合并 → 第 4 步的记录无法拆回 → 「归属冲突」中指定归属。

## 文件

- `core.py` — 引擎：SQLite 表结构、规范化、匹配、合并、撤销、血缘
- `app.py` — Flask 页面：客户 / 来源记录 / 导入 / 待确认 / 对比 / 合并记录 / 归属冲突
- `seed_demo.py`、`demo_imports/*.json` — 虚构演示数据
- `test_e2e.py` — 端到端自测
